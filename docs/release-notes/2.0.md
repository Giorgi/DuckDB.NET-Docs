# DuckDB.NET 2.0

This page lists the changes in DuckDB.NET 2.0 releases, newest first. For other versions, see [Release Notes](../release-notes.md). DuckDB.NET 2.0 has breaking changes. [Upgrading to 2.0](../upgrade-to-2.0.md) describes what they mean for existing code.

Thanks to Alaric Dailey ([@alaricd](https://github.com/alaricd)) for his pull requests that brought DuckDB.NET's ADO.NET behaviour in line with the documented contracts, and to Michał Rusinek ([@Mr444-dev](https://github.com/Mr444-dev)) for TIME_NS support.

## 2.0.1

Not released yet ([changes since 2.0.1-preview.1](https://github.com/Giorgi/DuckDB.NET/compare/80c39f44b3a8...develop)). Built on DuckDB [v2.0.1](https://github.com/duckdb/duckdb/releases/tag/v2.0.1).

The first stable release of DuckDB.NET 2.0. It includes the changes of the previews below. If you upgrade from 1.5, read [Upgrading to 2.0](../upgrade-to-2.0.md).

#### New features

- A timestamp table function parameter can be read as `DateTimeOffset`, the instant at UTC ([#397](https://github.com/Giorgi/DuckDB.NET/issues/397)).

#### Breaking changes

- A HUGEINT or UHUGEINT table function parameter read with `GetValue<object>` is an `Int128` or `UInt128`, as a column is. In the previews it was a `BigInteger`. Read it with `GetValue<BigInteger>()` to get one. The same applies to `DuckDBValue.GetValue<T>` in the bindings.

#### Fixes

- A `byte[]` returned by a scalar or table function is written to a BLOB column. Before, it threw ([#395](https://github.com/Giorgi/DuckDB.NET/issues/395)).
- A `DateOnly` or `DuckDBDateOnly` written to a TIMETZ or timestamp column, and a `DateTime` written to a TIMETZ column, throw `InvalidOperationException`. Before, a date in a timestamp column made every value in the chunk wrong, and a `DateTime` in a TIMETZ column was stored as a timestamp. This applies to the appender and to the results of scalar and table functions.
- A table function parameter can be read as `Int128?`, `UInt128?`, `DuckDBDateOnly?` and `DuckDBTimeOnly?`. These threw `InvalidCastException`.

## 2.0.1-preview.1

Released 2026-11-20 ([NuGet](https://www.nuget.org/packages/DuckDB.NET.Data.Full/2.0.1-preview.1), [changes since 2.0.0-preview.1](https://github.com/Giorgi/DuckDB.NET/compare/4df9b32e1f71...80c39f44b3a8)). Built on DuckDB [v2.0.1](https://github.com/duckdb/duckdb/releases/tag/v2.0.1).

#### New features

- `DuckDBArrowAppender` appends Apache Arrow record batches and streams to a table. Create it with `connection.CreateArrowAppender(table)`, then call `AppendBatch`, `AppendStream` or `AppendStreamAsync`. See [Arrow Appender](../arrow-appender.md).
- A table function over a collection tells DuckDB how many rows it returns. The length of an array is passed as exact, and the count of a `List<T>` or another collection as an estimate.
- An integer or decimal parameter is sent with the exact type of its parameter when the value fits, so DuckDB doesn't bind the statement again on every execution.
- `DbType.Decimal` and `DbType.DateTime2` are sent as DECIMAL and TIMESTAMP in any culture ([#382](https://github.com/Giorgi/DuckDB.NET/issues/382)).

#### Breaking changes

- A `DbType` assigned to a parameter is kept when `Value` is assigned afterwards ([#369](https://github.com/Giorgi/DuckDB.NET/issues/369)), and it decides the value. The value is converted to the .NET type of the `DbType` when nothing is lost, and refused with an `InvalidCastException` otherwise. `DbType.Int32` with 2.5 or `"42"`, `DbType.String` with 42 and `DbType.Boolean` with 1 are refused. Call `ResetDbType()` to send a value as its own type.
- With Dapper, `DynamicParameters.Add(name, 2.5, DbType.Int32)` is refused.
- A new parameter's `DbType` is `Object` (it was `String`), `ResetDbType()` returns to the type of the current value, and a `decimal` gives `DbType.Decimal` (it was `Currency`, [#382](https://github.com/Giorgi/DuckDB.NET/issues/382)).
- `DbType.Time` with a negative `TimeSpan` or one of a day or more throws `InvalidCastException` (it threw `ArgumentOutOfRangeException`). An INTERVAL parameter takes any `TimeSpan`.
- For an integer parameter, a `decimal` 2.5 rounds to 3 (it gave 2), and a `char` is sent as text, so `'5'` gives 5 and `'A'` is refused. A fraction in a comparison is no longer rounded first, so `WHERE i = $1` with 1.5 matches nothing. A value that doesn't fit is refused by DuckDB.
- A `double`, `float`, `decimal` or `bool` passed to a function argument that DuckDB types as an integer fails to bind, for example `substring('abcdef', $1, 2)` with 3.0.
- A value sent as text never depends on the current culture, and a list item without a `DbType` is sent as its own type.
- `CardinalityHint.IsExact` means what its name says, as DuckDB 2.0 corrected it. `false` is an estimate, and `true` is an exact count that DuckDB also takes as the most rows the function can return. A table function that passed `true` for a guess should pass `false`.
- A LIST or MAP read into a type that can't hold it throws `InvalidCastException`. This covers interfaces and abstract classes such as `IEnumerable<int>` and `IDictionary<K, V>`, types that aren't an `IList` such as `HashSet<int>`, and types that aren't an `IDictionary` such as `List<KeyValuePair<K, V>>`. Before, they threw `MissingMethodException`, `ArgumentException` or `InvalidOperationException`.

#### Bindings

- New features: bindings for `duckdb_schema_from_arrow`, `duckdb_data_chunk_from_arrow` and `duckdb_destroy_arrow_converted_schema`, with the `DuckDBArrowConvertedSchema` handle.

## 2.0.0-preview.1

Released 2026-11-09 ([NuGet](https://www.nuget.org/packages/DuckDB.NET.Data.Full/2.0.0-preview.1), [changes since 1.5.6.1](https://github.com/Giorgi/DuckDB.NET/compare/7ac3220f8fe5...4df9b32e1f71)). Built on DuckDB [v2.0.0](https://github.com/duckdb/duckdb/releases/tag/v2.0.0).

#### New features

- `Int128` and `UInt128` ([#370](https://github.com/Giorgi/DuckDB.NET/issues/370)). HUGEINT and UHUGEINT are read as these types, and every other integer column, VARINT, a whole DECIMAL and ENUM can be read as them when the value fits. They can be appended with `AppendValue` and the mapped appender, used as scalar and table function types, and sent as parameters.
- `DuckDBCommand.Prepare()` prepares the statement and keeps it on the connection until the connection closes, shared by the commands with the same text that call `Prepare()`. A command with several statements isn't prepared.
- TIME_NS columns can be read and written as `TimeOnly`, `TimeSpan`, `DateTime` and `DuckDBTimeOnly` ([#386](https://github.com/Giorgi/DuckDB.NET/issues/386), [#387](https://github.com/Giorgi/DuckDB.NET/issues/387)).
- LIST, MAP and STRUCT columns are read into a `List<T>`, a `Dictionary<TKey, TValue>`, a class or a struct without boxing. Classes derived from `List<T>` or `Dictionary<TKey, TValue>` are read through their base. The common element, key and value types also work under Native AOT.
- `[AllowNull]` on a scalar function parameter makes it nullable, as `string?` and `[MaybeNull]` do.
- `GetFieldValue<byte[]>` reads a BLOB, also as a list item, map value or struct field ([#384](https://github.com/Giorgi/DuckDB.NET/issues/384)).
- `GetBytes` and `GetChars` read part of a BLOB or a string into a buffer, and return the length for a null buffer ([#377](https://github.com/Giorgi/DuckDB.NET/issues/377)).
- `GetSchema("DataTypes")` and the ADO.NET metadata collections describe DuckDB's types ([#364](https://github.com/Giorgi/DuckDB.NET/issues/364)).
- `GetValues` copies only as many values as the array holds ([#376](https://github.com/Giorgi/DuckDB.NET/issues/376)), and `Close()` can be called more than once ([#373](https://github.com/Giorgi/DuckDB.NET/issues/373)).

#### Breaking changes

- DuckDB.NET.Data 2.0 needs DuckDB.NET.Bindings 2.0. Upgrade both packages together.
- HUGEINT and UHUGEINT are read as `Int128` and `UInt128` instead of `BigInteger`, by `GetValue`, `ExecuteScalar`, `GetFieldType`, the schema tables, `DataTable` and values in lists, maps and structs. `sum()` of an integer column is a HUGEINT, so cast its result to `Int128`. VARINT stays `BigInteger`.
- `IDuckDBAppenderRow` has new members `AppendValue(Int128?)`, `AppendValue(UInt128?)`, `AppendValue(DateOnly?)` and `AppendValue(TimeOnly?)`. With C# 12, an integer constant passed to `AppendValue` is ambiguous, so give it the type of its column, for example `(int?)1`.
- `DuckDBDateOnly` and `DuckDBTimeOnly` convert to `DateOnly` and `TimeOnly` only explicitly. `dateOnly.Equals(duckDBDateOnly)` returns `false` and `dateOnly.CompareTo(duckDBDateOnly)` throws, so cast the DuckDB value first.
- A typed scalar function with no nullable parameter returns NULL for a NULL argument without being called, for a column as for a constant. In projects without nullable reference types this includes `string` and `object` parameters. Declare the parameter `string?` or mark it `[AllowNull]` to be called.
- A FLOAT, DOUBLE or DECIMAL value with a fractional part, read as an integer type, throws `InvalidCastException` instead of being rounded.
- A list item, map key or value or struct field read as a type it can't be read as throws `InvalidCastException`, where some of these reads threw `ArgumentException`. Reads that a column allowed now work there too.
- A BLOB is read as `byte[]` instead of `Stream` by `GetValue`, `ExecuteScalar`, `GetProviderSpecificValue` and as `object`. `GetStream` and `GetFieldValue<Stream>` still return a stream.
- A DECIMAL of more than 18 digits keeps the scale of its column, so 1.5 from a DECIMAL(38,4) reads as 1.5000.
- A DATE, TIMESTAMP, TIME, TIMETZ or INTERVAL read into an `object` property, or with `GetValue<object>` in a function, is the column's .NET type instead of the DuckDB struct.
- A table function parameter read with `GetValue<T>` as a type other than its own, `object`, a nullable or an interface of it throws `InvalidCastException`.
- An `Int128` or `UInt128` parameter is sent as a HUGEINT or UHUGEINT value instead of text.
- `ExecuteNonQuery` returns -1 instead of 0 for statements other than INSERT, UPDATE, DELETE, MERGE and COPY, and `RecordsAffected` gives the same count instead of always -1 ([#374](https://github.com/Giorgi/DuckDB.NET/issues/374)).
- `CommandType` defaults to `Text` and `Direction` to `Input` ([#372](https://github.com/Giorgi/DuckDB.NET/issues/372)).
- `GetOrdinal` falls back to a case-insensitive search, and throws `IndexOutOfRangeException` for a missing column ([#375](https://github.com/Giorgi/DuckDB.NET/issues/375)).
- `Prepare()` needs an open connection ([#378](https://github.com/Giorgi/DuckDB.NET/issues/378)).
- `Release` and `ReleaseAsync` with a savepoint name throw `NotSupportedException`, as the other savepoint methods do ([#380](https://github.com/Giorgi/DuckDB.NET/issues/380)).
- A class derived from `Dictionary<string, object>` is refused as a MAP target.

#### Fixes

- A STRUCT read into a C# struct gets the values of its fields. Before, every property was left at its default.
- A string with NUL characters is stored in full by the appender, the mapped appender, the results of scalar and table functions, and parameters. Before, it was cut at the first NUL.
- A `BigInteger` appended to a column other than HUGEINT or UHUGEINT throws `InvalidOperationException`. Before, its 16 bytes overwrote the values next to it.
- A `DateTime` appended to a TIME column stores its time of day.
- A `TimeOnly` written to a DATE, TIMETZ or timestamp column, and a `DateOnly` written to a TIME column, throw `InvalidOperationException` instead of storing the bytes of the other type.

#### Bindings

- Breaking changes:
  - DuckDB.NET.Bindings 2.0 needs DuckDB.NET.Data 2.0.
  - `DuckDBString.value` and the nested type `DuckDBString._value_e__Union` are removed. Read a string with `Length` and `Data`, and build a short one with `DuckDBString.TryCreateInlined`.
  - `NativeMethods.Value.DuckDBCreateVarchar` takes a non-nullable string. Use `DuckDBCreateNullValue` for NULL. A new overload takes UTF-8 bytes and keeps NUL characters.
  - `DuckDBStringInlined` is internal.
  - `DuckDBValue.GetValue<T>` gives the value as its own type, as `object`, a nullable of it or an interface it implements. Any other `T` throws `InvalidCastException`.
- New features:
  - `DuckDBHugeInt` and `DuckDBUHugeInt` can be created from an `Int128` and a `UInt128`.
  - `DuckDBType` has the DuckDB 1.5 types STRING_LITERAL, INTEGER_LITERAL, TIME_NS, GEOMETRY and VARIANT.
  - Bindings for `duckdb_prepared_statement_type`, `duckdb_clear_bindings` and `duckdb_create_varchar_length`.
- Fixes: some native function declarations were corrected to match `duckdb.h`.
